## 三、登记表填法说明（九列）

模板见 `backend/data/来源登记表-样例.csv`。正式表在阶段零由 lead 建 `backend/data/来源登记表.csv`（本任务只交样例，避免与后端 agent 的文件冲突）。

| 列 | 电子书怎么填 | 文章怎么填 | 硬性校验 |
|---|---|---|---|
| `source_id` | `S001` 起三位流水号，全表唯一 | 同左 | 唯一 |
| `title` | 书名，含卷次（如「图说长征 红一方面军卷」） | 页面原标题，一字不改 | 非空 |
| `publisher` | 出版社全称（须在白名单可匹配） | 发布机构全称（须在白名单可匹配） | 电子书不得留空 |
| `publish_date` | 出版年份，如 `2026` | 发布日期，如 `2026-10-19` | 非空；只允许「年代不详」这一个字面值作例外 |
| `url_or_path` | 已采集填 `data/raw/S002_红军长征记.pdf`；未采集先填核验通报 URL | 原文页面 URL | 非空 |
| `access_date` | 拿到文件当天 | 抓取快照当天（**必须记**，防链接失效） | 非空 |
| `license_note` | 至少「公开出版物」，再补版本/再版信息与通报页 URL | 至少「官网公开文章」，再补原载报刊与版次 | 非空 |
| `corpus_tier` | 一般 `核心` | 史料类 `核心`，理论与宣传类 `补充` | 只允许 核心 / 补充 |
| `media_type` | `电子书` | `文章` | 必填且二选一 |

采集动作提醒：文章必须同时保存 HTML 或 PDF 快照 + 链接 + 获取日期；扫描件必须先 OCR 并抽样核对，抽样不合格则该单元不入语料。

## 四、进度表与判定

### 4.1 单元数统计口径

- **电子书 1 部 = 1 个单元**（多卷本整套算 1 个单元，在 `title` 标卷次；拆成两个来源编号才算 2 个单元，须能各自给出出版社与年份）；
- **文章 1 篇 = 1 个单元**；
- 只统计**已通过白名单与出版社校验并登记齐备**的单元；未核到、OCR 抽样不合格、来源被剔除的不计入；
- 单元与卡片/事实条目是两个口径：一部书可切 20–40 条事实，一篇文 1–5 条，进度表只数单元。

### 4.2 目标与判定节点

| 项 | 数值 / 规则 |
|---|---|
| 正常目标 | **80 个单元**（电子书 8–15 部 + 官方文章 40–70 篇） |
| 降级线（下限） | **50 个单元** |
| 判定日 | **第 10 个自然日**（自阶段零启动日起算，启动日由 lead 在提交信息里确定并写入决策记录 000） |
| 判定规则 1 | 第 10 自然日凑到 50–79 单元 → **按实际数量继续推进，不等满 80**，在评测报告记实际单元数 |
| 判定规则 2 | 第 10 自然日低于 50 单元 → 触发降级，改按**最小可交付集：电子书 5 部 + 官方文章 45 篇 = 50 单元**执行，并把判定写入决策记录 001 的「降级触发」小节 |
| 阶段零退出条件 | 语料 ≥50 单元且登记表九列齐备率 100%（plan 阶段零退出条件） |
| 人手安排 | 采集是并行人力任务：三人小队各认领一类（党史著作类 / 本地史料类 / 官方文章类）；单人则每天固定 2 小时，宁可停在 50 单元，不挤占阶段一编码时间 |
