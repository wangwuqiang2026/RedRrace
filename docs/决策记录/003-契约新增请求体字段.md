# 决策记录 003 —— 契约新增请求体字段 `AskRequest`（阶段零F）

- **编号**：003　**日期**：2026-11-13　**状态**：已生效（阶段三照此实现，前端类型由此生成）
- **负责人**：backend-core（模型与实现）／frontend-dev（类型消费）／lead（裁决）
- **依据**：`plan.md` 阶段三「接口约定」（`AskRequest` 提问请求：问题、召回条数、身份：学生／教师／馆员）与全局约束 10「契约优先于实现」；准入条件第 5 条「可回滚」
- **影响文件**：`backend/app/qa/schemas.py`、`backend/app/qa/router.py`、`backend/tests/test_qa_schemas.py`、`backend/openapi.json`（生成物）、前端 `src/api/*` 生成类型

## 一、决定

**本条属于简报外新增**：F1 简报只列了 `Locator`／`SourceOut`／`Citation`／`ConflictItem`／`AnswerOut` 五个响应侧模型，实现时补了一个请求侧模型 `AskRequest`：

```python
class AskRequest(BaseModel):
    question: str
    top_k: int = 8
    role: Literal["学生", "教师", "馆员"] = "学生"
```

理由一句话：`/api/ask` 是 POST，**没有请求体模型就没有 `requestBody`**，openapi 里只剩响应结构，前端仍要猜字段名——而这正是阶段零F 要消灭的东西。

字段取值不自行发明：`question` 沿用 plan 阶段三测试里的 `json={"question": ...}`；`top_k` 默认 8 取自 plan 阶段二/三示例的 `k=8`／`search(q, 8)`；`role` 三个值是 plan 接口约定的原文（学生／教师／馆员）。

## 二、怎么验证（已落测试）

- `test_ask_request_defaults`、`test_ask_request_role_is_a_closed_set`：默认值与身份闭集。
- `test_ask_request_field_names_and_types_are_locked`：字段名集合与类型、默认值逐一断言。
- `test_contract_model_field_names_are_locked`：五个响应模型的字段名集合一次锁死。
- 捕获力经变异实测（非声称）：把 `top_k` 改名 `top_n` → 2 条测试红（`AttributeError` + 字段断言失败）；把 `suggestions` 改名 `suggests` → 字段锁测试红；两次均恢复并校验 SHA-256 一致。

## 三、回滚方式

若 lead 或阶段三认定该模型不该在此时定：删除 `schemas.py` 里的 `AskRequest` 类、把 `router.py` 的 `ask(payload: AskRequest)` 改为不带请求体的占位、删上述三条测试，前端把 `ask` 的请求类型改回手写即可。**回滚不影响响应侧契约**（`AnswerOut` 等五个模型独立），也不需要动数据库或解析层。

## 五、类型生成工具的能力边界与「条数 / 顺序」的分工（D5，2026-11-13）

起因：visual-qa 实测纠正了一条**由 lead 先说出、若不落档会被阶段三/四照错话设计**的口径。以下三件事按 lead 要求分列，全部结论带本机实测出处（工具 `grep`/读原句，非推断）。

### 5.1 工具能力边界（哪个版本、哪个字段、生成物里表现为什么）

| 项 | 实测事实 | 出处 |
|---|---|---|
| 工具与版本 | `openapi-typescript` **^7.13.0**，锁定 `openapi-typescript@7.13.0(typescript@5.9.3)` | `frontend/package.json` 的 `gen:api` 脚本与 devDependencies、`frontend/pnpm-lock.yaml` |
| openapi 规范里**有没有**数量约束 | **有**：`ConflictItem.sides` 带 `"minItems": 2`、`"maxItems": 2` | `backend/openapi.json`（由 `schemas.py:74` 生成） |
| 生成物里**表现为什么** | 生成的是普通数组类型 `sides: components["schemas"]["Citation"][]`——**没有**定长 tuple（`[Citation, Citation]`）。即长度约束在类型面上**丢失** | `frontend/src/api/types.ts:121` |
| 结论 | 7.13 不会把 `minItems/maxItems` 映射为定长 tuple。所以「恰好两条」在前端类型系统里**不可表达、也不受检查**，TypeScript 编译期给不了任何保证 | 同上 |

### 5.2 分工结论（条数与顺序**分别**归谁，且顺序的归法与 lead 原话不同）

- **条数（恰好两条）＝后端契约层拦，前端 throw 是防御性第二层。**
  后端：`backend/app/qa/schemas.py:74` `sides: list[Citation] = Field(min_length=2, max_length=2)`；`:67-68` 的模型说明写明「拦截点提前到契约层（审查 I3），违反不变式的对象连构造都过不了」。
  前端：`frontend/src/api/adapter.ts:110-111` `sides.length !== 2` 直接 `throw`，并注明「拒绝截断或补位」。
  因此 lead 13:2x 那句「拦截发生在契约层、前端 throw 是第三层」**层数不对：前端侧只有两层（契约层生成物无约束 → 适配层 throw）**，本记录按实测写为「契约层拦 + 前端防御性第二层」。该表述更正由 lead 转告 frontend-dev 的注释，本岗不改 `frontend/**`。

- **顺序（恒 `source_id` 升序）＝前端适配层负责，且必须始终负责——但理由与 lead 那句不同，必须写准。**
  实测更正：**后端 pydantic 并非「只管条数不管顺序」**——`schemas.py:78-82` 会取 `ids` 并在 `ids != sorted(ids)` 时抛 `ValueError("sides 顺序恒为 source_id 升序…不得由调用方决定谁排前面")`；`router.py:17` 用 `response_model=AnswerOut`，输出同样过模型校验。
  准确的分工是：**后端管顺序的方式是「拒绝违约对象」，不是「替调用方重排」**；它绝不会把乱序静默纠正成升序。所以：
  1. 前端**不能**依赖类型系统（5.1：约束根本没进类型）；
  2. 前端**也不能**指望后端兜顺序——后端兜的方式是让请求/响应失败，而不是排好序交给前端；
  3. 前端必须自己排且始终自己排：`adapter.ts:113-115` 用 `compareSourceCodepoint` 做 Unicode 码点序排序，`:32` 注明「契约级排序＝码点序，与后端 Python `sorted()` 同序」，输出恒为 `[sides[0], sides[1]]` 两条并列。
  一句话：**「顺序的正确性」= 后端拒绝 + 前端排序 两层共同成立，前端那一层不可撤除，也不因契约层存在而可以省略。**

### 5.3 变更纪律（换工具、升版本、改生成流程时必须做的事）

1. 任何**类型生成工具替换或版本升级**（含 `openapi-typescript` 大/小版本、`--root`/`--enum` 等参数变更、或改用其他 codegen），必须**重跑 visual-qa 的三形态实验**确认拦截层没有**假移位**：① 把适配层排序整行删掉 → 必须仍能看到冲突展示退化（证明前端那层是真防线，不是摆设）；② 把语义清零（`sides` 内容相同化）→ 展示与文案不得自称「两处记载不一致」；③ 喂违约 JSON（`sides` 长度为 1 或 3、或顺序非升序）→ 后端 422/构造失败 与前端 throw 至少各命中一次，且**谁命中要能被日志区分**。
2. **禁止的推理**：不得假设「生成物里没写 = 后端管了」。5.1/5.2 已经证明两个方向都会错——长度约束规范里有、类型里没有；顺序规范里根本没有（JSON Schema 表达不了），但 pydantic 构造期在管。结论只能来自读 `openapi.json` + 读生成物 + 读两侧代码，不能来自猜测。
3. **留档要求**：若某天生成物真的出现定长 tuple（升级或换工具的结果），必须回来更新本节 5.1 与 5.2，并检查前端是否因此**撤除**了 `adapter.ts:110-113` 的显式校验——**撤除即视为回归**，类型收紧不等于展示层免责（顺序仍要前端排）。
4. 本节与 `docs/决策记录/000-语料来源与白名单.md` 第五轮「媒体族归一」共同构成阶段四的两条前提：**条数与顺序由本节管，「算不算两个来源」由第五轮管**。两者不得互相代替。
