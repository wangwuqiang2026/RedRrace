## 一、决定什么

**把语料来源从「协调校史馆等外部单位提供」改为「项目组自行搜集电子书 + 采集权威官方发布文章」，并配套定下白名单准入规则。**

plan.md 全局约束第 1 条与阶段零步骤 6 已按这个口径写；选题书 7.(1) 把「语料需要协调」列为最大非技术风险，本记录说明为什么可以绕过协调、风险变成了什么、以及怎么回滚。

## 二、为什么改（原因与代价）

| 维度 | 原路径：协调校史馆 / 外部单位供料 | 新路径：自行搜集 |
|---|---|---|
| 卡点 | 需要对方审批、专人对接、拷贝或开放权限，时间不可控，且「能不能给」不由我们决定 | 不依赖任何外部审批，第一天就能开工 |
| 风险性质 | 外部协调风险（不可控） | 内部核验工作量风险（可控，但要花时间） |
| 合规面 | 非公开档案、内部资料多，触碰 plan 禁止项的概率高 | 只用公开出版物与官网公开文章，天然避开「非公开档案」这条红线 |
| 质量面 | 材料形态杂，可能全是扫描件 | 可自选：优先取文字版电子书与网页正文，OCR 错字对逐字引文定位的威胁更小 |
| 代价 | 可能整段时间空转 | 来源核验、出版社核验、域名核验约 12–18 小时人力（plan 阶段零末尾的并行采集估算） |

代价换收益的判断：本项目对「出处可点开核验」是硬要求，自采路径反而更容易满足；校史馆材料今后若能拿到，按白名单准入规则作补充来源追加即可，不影响主链路。

## 三、白名单准入规则（定稿）

1. **两类比对键**：文章按发布机构比对 `name`/`aliases`；电子书按出版社比对 `name`/`aliases`。机构名归一规则：去空白与全半角差异后，与 `name` 或任一 `alias` 完全一致才算命中（不做模糊匹配，避免「××日报」误配到「××日报报业集团」之外的实体）。
2. **机构条目的域名未核实清楚的不入名单**（即不得 `verified: true`），宁缺毋滥；本次 `verified: false` 的条目保留在文件里但明确「不得入库」，防止后续误当已核。出版社条目不看域名看书目依据，规则见第 3 条。
3. **出版社条目的 `verified` 语义（2026-11-13 lead 裁决补入，因发现样例登记表与闸门规则自相矛盾）**：电子书的核验对象是「这本书确实由该正规出版社出版」，依据可以是 ① 出版社官网（含新书/书目页）② CIP 数据 ③ ISBN 记录 ④ 国家新闻出版署备案页 ⑤ 权威机构网站上的书目页或出版通报页，**不要求出版社必须有独立域名**；`domain` 允许为空字符串而 `verified` 仍为 true，但 `note` 必须写明实际核验依据（引到具体页面与原话）。`verified: false` 的条目一律视为不在白名单内，`registry.py` 拒绝入库。
4. **电子书两证齐全**：出版社条目 `verified: true` **且** 该书有一份可打开的页面确认书名 + 出版社（能确认出版年份最好）；缺一不得入库。
5. **文章三证齐全**：机构 `verified: true`、可打开的原文 URL、获取日期（快照同时保存）。
6. **增补即登记**：新增机构/出版社要在此文件追加一条记录，写明核验方式（A 直连实测 / B 官链交叉 / C 书目通报页）、日期与 `verify_source`。
7. **禁止项不变**（plan 全局约束第 1 条）：无出版社信息的扫描件、盗版下载件、白名单外自媒体、无署名转载、盗链、非公开档案。

### 第二轮补核与样例可入库性实测（2026-11-13，响应当天 lead 裁决）

- 处置：按裁决放宽并写清出版社的 `verified` 语义（第三节第 3 条），同时补核出版社，**不为让样例通过而假标 true**：中央文献出版社（正文显式社名 2 条）、人民出版社（书目页 + 来源署名，强度中，已在 note 里写局限）、新华出版社（官网直连实测）转为 `verified: true`，新增中国工人出版社（正文显式社名）。
- 白名单现状实测（脚本统计）：**18 个条目，`verified: true` 16 条，`verified: false` 2 条**（中共党史网、本校官网与校史馆）。
- 样例登记表可入库性实测（同一脚本按 registry 规则模拟：编号唯一、标题/链接/获取日期/发布日期非空、`corpus_tier` ∈ {核心,补充}、`media_type` ∈ {电子书,文章}、电子书必须有出版社与出版年份、publisher 归一后必须命中 `verified: true` 条目）：**5 行全部 PASS，无 whitelist 拒绝**——S001 文章（中国档案报）、S002 电子书（解放军出版社）、S003 电子书（中共党史出版社）、S004 文章（中国共产党新闻网）、S005 文章（中国方志网）。
- 样例本身未改动，因为矛盾根因在白名单侧的语义，已在源头修正；若日后某家出版社被降回 `verified: false`，对应样例行须同时改掉或在 `license_note` 标注「该出版社待核验，本行仅为格式示例，不可直接入库」。

**明确区分实测与推测**：本次没有出现「凭记忆写域名或写书目」的情况；未实测的一律 `verified: false` 或「候选，需核实出版社」，没有伪装成已核。

## 六、回滚方式

本记录的回滚 = 把语料来源口径退回「协调外部供料」，代价是重新承担选题书 7.(1) 的非技术风险。

1. **文档层**：删除或改写本文件；`docs/合规与引用政策.md` 第一节「先定白名单」需同步改回「以校史馆提供材料为准」；`backend/data/语料征集清单.md` 第一节书单作废（书单本身仍可留作公开出版来源）。
2. **数据层**：`backend/data/来源白名单.yml` 是唯一的准入名单。回滚时两种做法：
   - 全量回滚：删除该文件（`registry.py` 应改为不做白名单校验，同时必须删掉 `test_registry_rejects_source_off_whitelist` 这条测试，否则 CI 失败）；
   - 保守回滚：保留文件但把条目逐条改 `verified: false`，等价于「名单空置，一切来源都需人工放行」。
3. **已采语料**：外部协调材料若后续到位，属于「补充来源」，须重新走准入规则第 2、4 条（机构核验 + 三证齐全）才能追加，不影响已入库的公开语料。
4. **代码联调点**：`registry.py` 读取的字段名固定为 `name / domain / sections / aliases / verified / verified_at / note`（本阶段另加 `verify_source`，为可选追加字段，不影响旧读法）。回滚或换结构时，先改测试再改前端与文档，遵守 plan「接口向后兼容」。
5. **提交纪律**：本任务的五个文件均未 `git add`，由 lead 统一提交；提交信息建议 `docs(阶段零): 合规政策、来源白名单与语料征集清单`。
