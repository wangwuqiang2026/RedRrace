## 一、决定什么

**把语料来源从「协调校史馆等外部单位提供」改为「项目组自行搜集电子书 + 采集权威官方发布文章」，并配套定下白名单准入规则。**

plan.md 全局约束第 1 条与阶段零步骤 6 已按这个口径写；选题书 7.(1) 把「语料需要协调」列为最大非技术风险，本记录说明为什么可以绕过协调、风险变成了什么、以及怎么回滚。

## 二、为什么改（原因与代价）

| 维度 | 原路径：协调校史馆 / 外部单位供料 | 新路径：自行搜集 |
|---|---|---|
| 卡点 | 需要对方审批、专人对接、拷贝或开放权限，时间不可控，且「能不能给」不由我们决定 | 不依赖任何外部审批，第一天就能开工 |
| 风险性质 | 外部协调风险（不可控） | 内部核验工作量风险（可控，但要花时间） |
| 合规面 | 非公开档案、内部资料多，触碰 plan 禁止项的概率高 | 只用公开出版物与官网公开文章，天然避开「非公开档案」这条红线 |
| 质量面 | 材料形态杂，可能全是扫描件 | 可自选：优先取文字版电子书与网页正文，OCR 错字对逐字引文定位的威胁更小 |
| 代价 | 可能整段时间空转 | 来源核验、出版社核验、域名核验约 12–18 小时人力（plan 阶段零末尾的并行采集估算） |

代价换收益的判断：本项目对「出处可点开核验」是硬要求，自采路径反而更容易满足；校史馆材料今后若能拿到，按白名单准入规则作补充来源追加即可，不影响主链路。

## 三、白名单准入规则（定稿）

1. **两类比对键**：文章按发布机构比对 `name`/`aliases`；电子书按出版社比对 `name`/`aliases`。机构名归一规则：去空白与全半角差异后，与 `name` 或任一 `alias` 完全一致才算命中（不做模糊匹配，避免「××日报」误配到「××日报报业集团」之外的实体）。
2. **机构条目的域名未核实清楚的不入名单**（即不得 `verified: true`），宁缺毋滥；本次 `verified: false` 的条目保留在文件里但明确「不得入库」，防止后续误当已核。出版社条目不看域名看书目依据，规则见第 3 条。
3. **出版社条目的 `verified` 语义（2026-11-13 lead 裁决补入，因发现样例登记表与闸门规则自相矛盾）**：电子书的核验对象是「这本书确实由该正规出版社出版」，依据可以是 ① 出版社官网（含新书/书目页）② CIP 数据 ③ ISBN 记录 ④ 国家新闻出版署备案页 ⑤ 权威机构网站上的书目页或出版通报页，**不要求出版社必须有独立域名**；`domain` 允许为空字符串而 `verified` 仍为 true，但 `note` 必须写明实际核验依据（引到具体页面与原话）。`verified: false` 的条目一律视为不在白名单内，`registry.py` 拒绝入库。
4. **电子书两证齐全**：出版社条目 `verified: true` **且** 该书有一份可打开的页面确认书名 + 出版社（能确认出版年份最好）；缺一不得入库。
5. **文章三证齐全**：机构 `verified: true`、可打开的原文 URL、获取日期（快照同时保存）。
6. **增补即登记**：新增机构/出版社要在此文件追加一条记录，写明核验方式（A 直连实测 / B 官链交叉 / C 书目通报页）、日期与 `verify_source`。
7. **废止即留痕**（2026-11-13 lead 授权成文）：废止任何口径句时：原文保留、0 删除、就地加「本条已过时 + 现行值 + 出处 + 日期」标注；禁止改写成不含原词的表述，因为 `grep 归零` 抹掉的是可检索的教训。依据：D4（`docs/设计规范.md` §5.1.4 措辞封闭集登记）与 D5（`docs/决策记录/003-契约新增请求体字段.md` §四 过时标注）两次实操，lead 2026-11-13 授权成文。
8. **禁止项不变**（plan 全局约束第 1 条）：无出版社信息的扫描件、盗版下载件、白名单外自媒体、无署名转载、盗链、非公开档案。

### 第三轮（终审 I-2）：注释滞后于数据的成因与预防

- 现象：`来源白名单.yml` 出版社分组头注释仍写「已核到通报页 = true（三家）；未核到 = false（中央文献出版社、人民出版社、新华出版社）」，而数据里七家已**全部 `verified: true`**；注释还说「domain 一律留空」，而新华出版社 `domain: www.xinhuapub.com`。后果是采编人员按注释会误剔三个合法来源，或误以为 domain 必须留空。
- **成因（阶段一须防的同类错误）**：补核是「先改条目数据、后改分组说明」的两步操作，第二轮我只做了第一步——逐条 `verified`/`domain`/`note` 都改了，但分组头那段是上一版一次性写下的**汇总性散文**，没有随之重算；文件里没有任何机制强制汇总注释与条目一致（无脚本校验、registry 也不读注释），所以漂移不会被任何测试发现，只有人读得出来。
- 处置：注释按当前事实重写（七家全 true、逐家核验依据、点明只有新华有官网、domain 不是放行条件），并在白名单头部「书写纪律」加两条硬规定：① 改 `verified` 必须同步改分组头注释；② 布尔字段只写小写 `true`/`false`，不写 `yes`/`on`/`TRUE`（PyYAML 会把它们解析成 true 而放行；文档里「带引号的 `"yes"` 一律拒绝」是另一回事）。
- 连带两条 Minor（同批修入头部注释）：`name` 的「唯一」改为**「靠本文件人工保证，registry.py 不查重名」**的写实表述；`type` 分组字段确认**不加**（YAGNI，比对键仍由 `media_type` 决定）。

  - **人民日报系**：人民网·中国共产党新闻网 / 人民日报，以及转载稿中署名「原载：人民日报」者；
  - **中国档案报系**：中国档案报（含其主办的中国档案资讯网）/ 国家档案局（两站名一实）；
  - **方志系**：中国方志网、湖南省地方志编纂院及各省级方志机构公号（山东省情网、史志山西、江苏省地方志网等）。
- 判定效果：**同族内任意两单元 ≈ 一个来源**，不构成「多来源交叉验证」；「两处记载不一致」必须来自**跨族**单元对。

**口径 2：判定依据只用登记表 `license_note` 与快照署名解析，不回抓快照**（可执行规则，供阶段四实现）：
1. `license_note` 或快照正文含「原载〈X〉」/「来源：X」/「来源〈X〉」 → **归 X 所属媒体族**，此时**原载方覆盖发布方**（例：求是网 S043 署名原载新华网 → 归新华系，而非按「求是网」当独立一家）；**X 不在口径 1 四族之内时，X 自成一族、按独立来源处理**（例：原载《光明日报》《解放军报》《农民日报》者各自成族，**不得并入人民日报系**），新增族成员须先追加本记录再改解析表。
   > **lead 裁决（2026-11-13）：本项「不升格、不并族」为最终口径。** 理由：并入人民日报系是**替史料关系做没有证据的推断**；一旦并了，「解放军报原载 + 求是网转载」就会被判同族而**误杀真交叉**（明明两处记载却被当成一个来源）。自成一族的代价只是「转载稿仍可能被当独立来源」，属**偏保守方向——宁松勿误杀**。**「原载方覆盖发布方」是本判定的主键，不得弱化或绕开。**
2. 命中「转载」字样但**无外机构署名** → **按独立单元处理**并打标记（实测 S017 即此例）；
3. 解析正则有边界留痕：署名串截到「发布时间」或书名者属误判，已剔除 2 处（S019、S064），实现时必须同样**宁可漏判不可误判**；
4. 族归属是**入库时的静态属性**（写入条目或登记备注），不是每次查询重算，避免同一事实在不同轮次得到不同的「来源数」。

**口径 3：转载单元不删除。** 转载稿作为阅读材料与定位来源仍然有效、参与检索召回；但**不得作为独立来源参与冲突判定与「多来源一致」计数**。一句话记法：**能引、能定位，不能当第二家。**

**口径 4：跨族才成立（正反例固定，阶段四拿这组做验收样本）。** 14 组重叠对里涉转载的 4 组处置（实测）：
- **P9 于都出发＝跨族成立**（S014 档案报系 ↔ S043 求是转载·原载新华）——范例；
- **P3 大渡河/泸定桥＝同族同源剔除**（S156 新华 ↔ S051 求是转新华网稿；署名「来源：新华网」+ 与 S156 有 30 字最长公共段）——反例；
- **P5 六盘山、P11 将台堡＝同属新华系，存疑剔除**（不同记者稿仍同族）；
- 结论：**14 组中可作阶段四「两来源」使用的是 11 组，剔除 3 组（P3、P5、P11）**；转载稿共 **24 篇 / 171 = 14.0%**；「同一原稿被三家同时登记」＝**0 组**。

**口径 5：站点模板公共块不是史料，解析层必须剔除。** 此前所有 0.5x 相似对全部来自**中国方志网侧栏「图片新闻 / 最新更新」那块 1014 字公共模板文本**，段落级清洗后归零。风险说清：若不清掉模板块，一条**假引文**可能在 171 篇里**全部逐字命中**，凭空造出「多来源一致」——这比漏检更危险，因为它会主动骗过引用校验器。**代码侧已派 backend-core 修 HTML 解析（终审编号 I8）**；规范侧要求：解析产物必须能区分正文区与导航/侧栏区（`Block` 带 `region`），冲突判定与引文定位只准用正文区块。

**验证要求（阶段四不得跳过）**：族归一上线时，必须有一条测试拿 **P3 大渡河**当样本证明「同族两单元不计作两来源」，拿 **P9 于都**证明「跨族成立」；只测正向不测反例等于没上线。杀用例（阶段四 5–6）另计，与本条互不替代。


**明确区分实测与推测**：本次没有出现「凭记忆写域名或写书目」的情况；未实测的一律 `verified: false` 或「候选，需核实出版社」，没有伪装成已核。

## 六、回滚方式

本记录的回滚 = 把语料来源口径退回「协调外部供料」，代价是重新承担选题书 7.(1) 的非技术风险。

1. **文档层**：删除或改写本文件；`docs/合规与引用政策.md` 第一节「先定白名单」需同步改回「以校史馆提供材料为准」；`backend/data/语料征集清单.md` 第一节书单作废（书单本身仍可留作公开出版来源）。
2. **数据层**：`backend/data/来源白名单.yml` 是唯一的准入名单。回滚时两种做法：
   - 全量回滚：删除该文件（`registry.py` 应改为不做白名单校验，同时必须删掉 `test_registry_rejects_source_off_whitelist` 这条测试，否则 CI 失败）；
   - 保守回滚：保留文件但把条目逐条改 `verified: false`，等价于「名单空置，一切来源都需人工放行」。
3. **已采语料**：外部协调材料若后续到位，属于「补充来源」，须重新走准入规则第 2、4 条（机构核验 + 三证齐全）才能追加，不影响已入库的公开语料。
4. **代码联调点**：`registry.py` 读取的字段名固定为 `name / domain / sections / aliases / verified / verified_at / note`（本阶段另加 `verify_source`，为可选追加字段，不影响旧读法）。回滚或换结构时，先改测试再改前端与文档，遵守 plan「接口向后兼容」。
5. **提交纪律**：本任务的五个文件均未 `git add`，由 lead 统一提交；提交信息建议 `docs(阶段零): 合规政策、来源白名单与语料征集清单`。
