# 决策记录 005 —— 向量化改走 API，本地 bge-m3 降为兜底（2026-11-16）

- **日期**：2026-11-16
- **触发**：用户对下一步的明确指示两条 —— ①「**不要下载模型，到时候用向量模型的 API**」；②生成后端选**在线 API**。
- **决定**：
  1. **向量化默认走 API**（OpenAI 兼容 `/embeddings` 形态，**不绑定供应商**：通义 DashScope、其他兼容端点均可，由配置选择）；
  2. **本项目不再下载 bge-m3 权重**，本地 bge-m3 / GGUF 路线**保留为可替换点与离线兜底**，不作为默认路径；
  3. 生成后端 = 在线 API（`llm_backend=online`），本地 GGUF 仅用于阶段八离线演示与阶段九降级演练。
- **性质**：技术栈内的可替换点变更（plan「技术选型与可替换约定」向量模型一行）。**五条不变契约、接口路径与字段名、前端框架、SQLite 存储全部不动。**
- **合规前提（缺此即不得通过本记录）**：全局约束 6 与准入条件 2 明文要求「**不得把付费云服务设为唯一路径**」。因此本变更**必须**同时落地三级降级：`api` → `local`（本地向量模型，按需才下载）→ **BM25-only 稀疏检索**（无向量也可答，见第四节）。降级路径不实现，本记录作废。

## 三、连锁后果（四条，每条都要落到计划动作）

1. **拒答阈值与 `term_floor` 必须在实际用的向量模型下重标**。换 embedding 模型 = 换相似度分布，参考实现 §9.4 实测过五个模型 Hit@1 从 36.7% 到 60.0% 不等。plan 阶段二步骤 6b 的「本项目从 0.40 扫到 0.60、不得直接采用 0.45」这条纪律**同样禁止沿用 bge-m3 假设值**；`EMBEDDING_MODEL` 或 `EMBEDDING_DIM` 一旦变更，语料指纹之外还要比对向量配置签名，签名不符索引判过期重建（参考实现 §5.37 实测坑：向量缓存是进程级，切模型后不失效）。
2. **索引实现改向 SQLite**：条目 ≤ 数千、1024 维 float32 量级约几 MB，plan 阶段二原文已写「规模小无需近似索引」，故 `faiss-cpu` 非必需。`Hit` 结构不变；若将来条目量级上升再按可替换点装 `retrieval` extra 换 FAISS，属内部实现替换。
3. **阶段八冷机指标含义变更**：「建索引 ≤10 分钟」不再衡量 CPU 编码吞吐，而衡量 **API 批量向量化的网络往返 + 限流 + 失败重试**，必须记录调用次数、输入 token 数、P50/P95（阶段九步骤 3b 的成本单列已覆盖，此处只需把「向量化调用」纳入统计项）。
4. **稀疏通道自检的权重上升**：BM25 从「防中文零命中的坑」（阶段二步骤 3b）升级为**向量 API 不可用时的降级主路径**。因此 3b 那条 `search_bm25_only` 测试通过之后，还要加一条「`EMBEDDING_BACKEND=stub` 时检索链路仍返回有序结果、且拒答闸门在无向量分时的行为符合阶段二步骤 4b 的 `None` 语义」——否则降级线只是纸面。

### 7.2 本机实测（2026-11-16，无 key 的通路探测，不计费）


### 7.3 对本项目的四条结论

1. **合适，且比原基线更贴合 B 档硬件**：无显卡依赖、SQLite 存 1024 维 float32 约 1000 条仅 4 MB（原 001 维度 3 的内存推论不变）；建索引按 400 条 ÷ 批量 16 = **25 次请求**，RPM 24,000 与 TPM 1,000,000 远未触及，**阶段八「建索引 ≤10 分钟」的瓶颈从向量化挪回到电子书解析/OCR 一侧**（这条要如实写进冷机记录，别把功劳记在检索层）。
2. **成本不是约束**：400 条 × 检索串约 200 token ≈ 80K token ≈ **0.01 元/次全量重建**（Batch 半价约 0.005 元）；问句侧每题 1 次调用。100 万免费 token 足够支撑整个开发周期，答辩与降级演练也不需要考虑额度耗尽之外的失败模式——但限流与网络抖动仍要按 `.env.example` 的 `EMBEDDING_TIMEOUT_S` / 重试逻辑处理（本记录第二节）。
3. **学不到它的稀疏能力，且这里有一个静默失败陷阱**：官方原文「**OpenAI 兼容接口不支持稀疏向量输出**……通过 OpenAI 兼容接口传入 `output_type=sparse` **会返回 HTTP 200，但 embedding 结果为空**」。「返回 200 却拿到空结果」正是参考实现 §2.1 那类最危险形态（不报错、静默降级）。因此本项目**稀疏通道只有自建 BM25 一条线**，plan 阶段二步骤 3b 的自检从「防中文零命中」升级为「**同时防 API 静默空返回**」：`ApiEmbedder` 必须断言响应向量数量 == 请求行数、每条维度 == `EMBEDDING_DIM`、且无空数组，任一不满足显式报错而非填空值。
4. **128K 能塞不等于该塞**：长文本上限从 32K 提到 128K 只消除「被截断」的风险，**不改善检索粒度**；参考实现 §5.7 实测按页整块 Hit@1 55.6%、512/64 切块 88.9%，粒度才是主因。所以 plan 阶段二**步骤 3c 的两档 A/B 照做不豁免**，且要在评测报告里写明：块大小由命中率决定，不由模型上限决定。

## 八、追加更正（2026-11-16，依决策记录 007 的带 key 实测）

本记录第七节成文时，模型名、维度、单价、上限全部只有官方文档为据。当日拿到 key 后做了三轮真实调用探测，**以下四条以本记录原文为"原口径"，按纪律保留原文、在此更正**：

| 本记录原口径 | 实测（007 章节号） |
|---|---|
| 「单次最大行数官方为 **20**」 | 服务端实际允许 **25**（26 即 400 回显 `should not be larger than 25`）。`EMBEDDING_BATCH_SIZE=16` 决策不变，但**校验逻辑不得把 21～25 判为非法**（007 三-1） |
| 「单行最大 128,000 token」 | 真实边界 **131,072**，且**明确 400、不静默截断**（007 三-2）；同批混入一条超长会**整批失败 `count=0`**，所以必须发送前逐条预检（007 三-3） |
| 第七节 7.2「模型名有效性未验证」 | **已验证可用**：dim=1024、1024 分量全非零（007 二）；`dimensions=768/512` 亦生效，且实测为 **MRL 前缀截断**（cos 0.9991），故改维度仍判索引过期（007 六-3） |
| 第三节第 1 条「换 embedding 端点等于换向量空间」 | **量级需大幅下修**：同 `text_type` 下兼容层与原生端点 cos 0.998478~1.000000，差异仅 1e-3。真正搬动向量空间的是 **`text_type`**：默认值在两端点**相反**（兼容层 `query` / 原生 `document`），漏传即 cos≈0.925 且全程 200（007 四）。本记录第三节的签名要求因此**扩容**：`EMBEDDING_MODEL` + `EMBEDDING_DIM` + 基址哈希 + **`text_type` 两侧组合** |

另外三条本记录未曾预料、需并入第四节降级纪律与阶段八自检的事实：① 空串输入返回**全非零向量**（服务端不报警，须客户端拒）；② 同参数两次调用向量 cos=0.999095，**非确定性**，故"索引可复现"只能按 cos 判、不得按哈希；③ `qwen3.8-flash` 属混合思考模型，`enable_thinking=false` 实测可关（本记录未考虑该参数，见 007 五）。
